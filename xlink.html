まず結論

今回、どこまで確認できた？

Windows 11環境で、GW-USNano2とGW-US54GXSの両方を使い、PSPのアドホックSSIDへの接続と、XLHAからXLink Kaiへの接続を確認しました。GXSではHostingをOFFにした状態でも接続できています。

OKPSPアドホック接続

重要：「PSPのSSIDに接続できた」＝「他プレイヤーとのクエストに成功した」ではありません。ドライバー・PC・PSPのCFWによって結果が異なる可能性があります。
インターネット ↔ Windows 11（XLink Kai ＋ XLHA）⇅ USB Wi-Fiアダプター（GXS / Nano2）PSP（CFW ＋ プラグイン） → MHP2G オンライン集会所

1. 準備するもの

  • Windows 11 PC（インターネット接続あり）
  • PSP本体、アドホック対応ゲーム（ここではモンスターハンターポータブル2nd G）
  • CFW導入済みPSP（XLHAのPlugin Device方式を使うため）
  • GW-US54GXS または GW-USNano2（同じ型番でも環境差あり）
  • XLink Kaiのアカウント（XTag）、XLink Kai、XLHA、Npcap
インターネットにPCのWi-Fiを利用している場合、PSP接続用には別のWi-Fiアダプターが必要です。PCを有線LANでインターネットにつなぐ方法もあります。

2. Wi-Fiアダプターの認識・ドライバー

A. GW-US54GXS（友人向け本命）

  1. GW-US54GXSをPCに差します。
  2. デバイスマネージャーを開きます（スタートを右クリック → デバイス マネージャー）。
  3. 「ほかのデバイス」にPCI GW-US54GXSと黄色い警告マークが出ても、ここではまだ失敗ではありません。
  4. PLANEX公式のWindows 7用ドライバー（2.2.0.27）をダウンロードして展開します。
  5. 該当デバイスを右クリック →「ドライバーの更新」→「コンピューターを参照してドライバーを検索」→ 展開先を指定して進めます（サブフォルダーも検索）。
  6. 「ネットワーク アダプター」に移動すれば、ドライバー適用の第一段階成功です。
Windows 7用ドライバーはWindows 11のメーカー保証対象外です。適用できない場合は無理に進めず、エラー内容を確認してください。ドライバー署名強制の解除・メモリ整合性の無効化は推奨しません。ドライバーは必ず公式配布元から。

B. GW-USNano2

今回の実機では、Windows 11上でMicrosoft提供のRealtekドライバー 1027.4.630.2015 により認識されました。すでにネットワークアダプターとして認識するなら、まずそのまま試します。 不用意に古いドライバーへ入れ替えないでください。

接続前の確認（コマンドプロンプトを使う）

Windows 11がWi-Fiアダプターを正しく認識しているか、接続前に確認します。確認にはWindows標準の「コマンドプロンプト」を使います。コマンドプロンプトを開いて、以下のコマンドを入力し、Enterキーを押すとWi-Fiの状態を確認できます。

netsh wlan show interfaces

結果の「状態」が「切断されました」でも、接続前なら異常とは限りません。接続後の確認方法と表示の見方は「7. 接続テストと成功の見分け方」を参照してください。

コマンドプロンプトの開き方やコマンドの入力方法が分からない場合は、ヘルプ：コマンドプロンプトの使い方をご覧ください。

3. 必要なソフトの導入

① Team XLink公式サイト：アカウント登録とXLink Kai入手 ↗② XLHA 1.2（GitHub Releases） ↗③ Npcap公式ダウンロード ↗
  1. XLink Kaiをインストールし、XTagアカウントでログインできるようにします。
  2. XLHAのリリースページで XLHA-WindowsX32-1.2.zip を入手します。「X32」ですが通常のWindows 11 x64でも32bitアプリとして動作します。展開先の例は C:\XLHA です。
  3. Npcapをインストールします。検証時は1.89を使用しました。XLHA 1.2のリリース説明では少なくともNpcap 1.60が必要とされています。
Npcapオプション検証時
Restrict ... to Administrators onlyOFF
Support raw 802.11 traffic (and monitor mode)ON
Install Npcap in WinPcap API-compatible ModeON

これらは今回の検証環境での値です。無線アダプターのアドホック対応を保証するものではありません。互換モードは既存WinPcap環境に影響する場合があります。

4. PSP側にプラグインを入れる

  1. PSPのCFWが有効なことを確認します。
  2. XLHAの公式Pluginフォルダー ↗から AdHocRedirectorWiFi.prx を用意します。ソースコードだけではなくPRX本体が必要です。手元の配布物に同梱されている場合も確認してください。
  3. PSPのメモリースティックに /seplugins/AdHocRedirectorWiFi.prx を配置します。
  4. CFWのプラグイン管理画面で、GAMEを有効にします。通常のUMD/ISOゲームを試すだけならHOMEBREWやPOPS、VSHは原則不要です。

従来の GAME.TXT 方式を使うCFWでは、既存の内容を消さずに次を追記します。

ms0:/seplugins/AdHocRedirectorWiFi.prx 1
PSP goの内蔵ストレージなら通常 ef0: を使用します。CFWによってプラグイン配置・有効化方法が異なるため、使用中のCFWのルールを優先してください。プラグイン変更後は必要に応じて再起動します。

5. XLHAの初期設定

  1. GW-US54GXS（またはNano2）を接続。xlinkhandheldassistant.exeを起動します。必要なら管理者として実行します。
  2. Step 1/3：Plugin Device を選択します。
  3. Step 2/3：Automatically connect to PSP networks はON。Use SSID from host broadcast はまずOFF。PSP用のアダプターを選択します。「Wi-Fi 2」等の名前だけでは判別せず、Win + R → ncpa.cplで機器名と対応を確認します。
  4. Reconnect after network has been inactive for (seconds)：初めは既定の15で試せます。今回の切り分けでは0も使用しました。0では自動再接続が制限されるので、接続し直すときは手動の Re-Connect が必要になる場合があります。
  5. Step 3/3：Kaiを同じPCで使うなら 127.0.0.1、ポート 34523（今回の設定）を維持します。34522はブラウザ用Web UIポートで別物です。
  6. 設定完了後、HUD（メイン画面）の Start Engine を選択します。
Hosting：通常の接続テストや他の人のゲームへ参加する場合はOFFで構いません。実際にゲームのホストを担当する場合はXLHAとKai側の案内に従って設定します。今回GXSはHosting OFFでもPSP接続を確認しました。

6. XLink Kai側の設定

XLink Kaiを起動してログイン。ブラウザUIは通常、次のアドレスで開けます。

http://127.0.0.1:34522/
項目今回の初期方針
アダプタ自動検索（XLHA Plugin / DDS方式ではKaiが直接無線カードを処理する必要がない場合がある）
ポート番号0（自動）
PATを許可ON
UPnP port forwardingまずOFFのまま
Web UI Port34522
PSP/PS3/PS4/PS5のIP自動割当ON
UIロスト後のエンジン終了時間終了しない（今回の検証値）
診断で Reachable: Yes が出ている間は、昔のようにUDP 30000の手動開放を急ぐ必要はありません。NAT Type: Moderate は実際の対人接続時に制約が出る可能性がありますが、PSPのSSID検出とは別問題です。

7. 接続テストと「成功」の見分け方

ここでは PSPとパソコンが本当に無線接続できているかを確認します。初めてWindowsのコマンドを使う方も、以下の順に進めてください。

7-1. PSP・XLHA・Kaiを接続状態にする

  1. PSP本体の無線LANをONにし、モンスターハンターポータブル2nd G（MHP2G）を起動します。
  2. PSPでオンライン集会所に入ります（確認中は退出しないでください）。
  3. XLink Kaiを起動・ログインし、PSP → Action → Monster Hunter Portable 2G の対応Arenaに移動します。
  4. XLHAで Start Engine を実行します。接続しなければ Re-Connect を試します。
  5. XLHAに Status: Running と Connected to: PSP_... が表示されるか確認します。この表示だけでは接続が継続している証明にならないため、次にWindows側も確かめます。

7-2. Windowsの接続状態を確認する

PSPとパソコンがつながっているかを、Windows標準の「コマンドプロンプト」で確認します。コマンドプロンプトを開いて下のコマンドを入力し、Enterキーで実行してください。アダプターの接続状態が表示されます。

netsh wlan show interfaces

操作方法に不安がある方は、ヘルプ：コマンドプロンプトの起動・入力方法を開いて確認してください。

ヘルプ：コマンドプロンプトの起動・入力方法（クリックで表示）

「コマンドプロンプト」は、Windowsに文字で指示を出すための標準ツールです。追加ソフトのインストールも管理者権限も必要ありません。

  1. キーボードの Windows キーを押したまま R キーを押します（Win + R）。
  2. 左下などに「ファイル名を指定して実行」という小さな画面が出ます。
  3. 「名前」の欄に cmd と入力します。
  4. Enter キー、または「OK」をクリックします。
  5. 黒い画面が開き、C:\Users\（ユーザー名）> のような文字が表示されれば準備完了です。ユーザー名は人によって違っていて正常です。
別の開き方：スタートメニューの検索欄に「cmd」または「コマンド プロンプト」と入力し、検索結果の「コマンド プロンプト」を開いてもOKです。

7-3. 表示されたアダプターを見分ける

表示された一覧から、GW-US54GXSまたはGW-USNano2に該当する項目を探してください。接続前は「切断されました」、PSPへの接続成功後は「接続されました」と表示されることがあります。

数秒で無線LANアダプターの状態が表示されます。複数のWi-Fiアダプターがある場合は、「説明」または「名前」からGW-US54GXS／GW-USNano2に該当する項目を探してください。「Wi-Fi 2」などの番号はPCごとに異なります。

7-4. 結果のどこを見ればいい？

接続成功時は、例えば次のような内容が表示されます（これは表示例で、すべて同じ文字になる必要はありません）。

名前                 : Wi-Fi 2
説明                 : （GW-US54GXS等のアダプター名）
状態                 : 接続されました
SSID                 : PSP_AULJM05500_L_MHP2Q000
ネットワークの種類   : アドホック
無線の種類           : 802.11b
確認する欄期待する内容何が分かる？
名前／説明対象のGXS／Nano2別のWi-Fiアダプターと取り違えていないか
状態接続されましたWindowsが無線接続中と認識している
SSIDPSP_で始まる名前PSP用ネットワークにつながっている
ネットワークの種類アドホックPSPのアドホック通信方式を利用している
「切断されました」と表示される場合：故障と決まったわけではありません。PSPがオンライン集会所に入っていること、XLHAで正しいアダプターを選んでいること、Re-Connectを実行したかを確認してください。「ハードウェア オン／ソフトウェア オン」でも、未接続なら「切断されました」と表示されます。
情報の共有に注意：結果には物理アドレス（MACアドレス）やBSSIDなどが含まれる場合があります。SNSやチャットにスクリーンショットを送るときは、それらを隠してください。必要なら「名前」「説明」「状態」「ネットワークの種類」だけ文章で伝えれば十分です。

7-5. XLink Kai側でも確認する

  1. ブラウザでXLink Kaiを開き、「診断（Metrics）」を選択します。
  2. Reachable: Yes と表示されるか確認します。これはKaiがネットワーク上で到達可能と判定した状態です。
  3. XLHAの接続通知を確認し、DDS App Traffic、Broadcast Trafficの値が変化するか見ます。
  4. 値がずっと0でも、それだけで失敗とは判断しません。逆に数値が増えても実際の2人プレイの成功までは保証しません。
今回の実機検証で確認できたこと：GW-US54GXS／GW-USNano2ともに、Windows 11が「接続されました／アドホック」と認識し、XLHAのPSP SSID表示とKai側のDDS通信を確認しました。これはPCとPSP間の無線接続、および中継処理の一部が機能した証拠です。
最後のゴールは対人プレイです。 別々のPSPとPCでKaiに接続し、同じオンライン集会所で相手のキャラクターが表示され、クエストに参加できるかを確認します。今回その段階までは未検証です。

8. つまずいたときの対策集

GXSが「ほかのデバイス」に黄色い！

未適用の可能性があります。PLANEX公式Windows 7用ドライバーを展開し、デバイスマネージャーから手動で検索します。ネットワークアダプターに移ったら一歩前進。ただしWindows 11での動作は保証外。

「切断されました」と出る

未接続の表示なら正常な場合があります。無線のハードウェア／ソフトウェアがONか確認し、PSPを集会所に入れてからXLHAを起動。netsh wlan show interfaces では機器ごとの状態を見てください。

XLHAのConnected表示が出ない

Step 2/3で正しいアダプターが選ばれているか、PSPがオンライン集会所にいるかを確認。Re-Connect を試し、改善しなければ Stop Engine → Start Engine。再接続時間0は初回接続以降の自動再試行を制限します。

Connected表示が消えない／古いSSIDのまま

XLHAの表示は最後の接続先が残る可能性があります。表示だけで判断せず、Windows側の netsh wlan show interfaces で実際のSSID・状態を確認します。

「Could not send Scan request Unknown error」

XLHAのWi-Fiスキャン要求失敗です。旧ドライバーとWindows 11の相性やアダプターの選択状態を疑います。何度も発生する場合、Options → Configure log level → Debugでログを取得。ドライバー変更や安全機能の無効化は最後の検討事項にします。

「Timeout waiting for XLink Kai to connect」

Kaiが実行中か、XLHA Step 3/3が 127.0.0.1:34523 か確認。接続後に XLink Kai succesfully connected と記録される場合もあります。ログの時刻を照合します。

Kaiに「UIとエンジンの接続に不具合」警告

まずKaiエンジンのプロセスが存在するか確認。エンジンが起動したままならブラウザだけ開き直して復帰する場合があります。XLHA停止で症状が収まるならXLHA連携・PSP接続状態を分けて確認。発生原因は今回も完全には特定できていません。

ログの場所・取得方法

XLHAの配置先にある log.txt を確認。Options → Configure log level → Debug にすると詳細が増えます。エラー発生直後の末尾を残してください。公開前にIPアドレスやMACアドレスは伏せます。

ポート開放は必要？

Kai診断が Reachable: Yes ならまずは不要です。実際の対人プレイで接続不良があるときに、NATやルーター、Kaiの公式FAQに従って検討します。無関係なポートをむやみに開けないでください。
